# ShotMatch feature test

Behaviour audit of every control on production (https://104-238-146-229.sslip.io), Sunday Nov 8, 2026, first pass 2:45 to 6:30 AM CT. The UI audit thread owns looks; this file covers what each control does and whether it keeps working when combined with others.

190 rows: 158 pass, 27 fail (0 blocker, 20 major, 7 minor), 5 not testable here.

## How it was tested

- Playwright on production in scratch shoots made from the example photo (KYKMBH, EGHGWU, WN6XNQ, VQCCN2 and one for panels), never in A9TVAN. Two people per shoot (TesterA, the owner, and TesterB), plus a third for the share link and the join gate, and a phone-sized scout.
- Each control: do the action, read the SpacetimeDB row with `spacetime sql`, check the second browser shows the same thing, reload where it matters, and read the console. Screenshots are in `web/screenshots/feature/`.
- The scripts are in `~/Code/scratch/shotmatch-agents/feature-work/` (`simple.mjs`, `studio-camera.mjs`, `studio-objects.mjs`, `studio-time.mjs`, `studio-panels.mjs`). `web/scripts/feature-smoke.mjs` re-runs the core paths.
- AI calls were kept to one per path: one Simple render, one Studio render, one prop generation, one critique, one call sheet, a few Nemotron set commands. No texts or calls went to real numbers; the email invite went to example.com.
- Rows marked "not testable here" need hardware or accounts the test browser lacks (VR, gyro, a real camera feed, Photon sending).
- Headless Chrome on linuxbox's integrated GPU lost its WebGL context twice under load. Rows hit by that were re-run with software GL; the crash itself is listed once as a minor resilience note, since a real laptop GPU is unlikely to hit it.
