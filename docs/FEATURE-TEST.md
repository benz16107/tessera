## How it was tested

- Playwright on production in scratch shoots made from the example photo, a Clifton Hill photo with GPS, a no-GPS Eiffel Tower photo and a no-GPS Glasgow street, never in A9TVAN. The test identities were:
  - two people per shoot (TesterA, the owner, and TesterB)
  - a third person for share links and the join gate
  - a phone-sized scout
  - second identities for collaborator checks
- Each control: do the action, read the SpacetimeDB row with `spacetime sql`, check the second browser shows the same thing, reload where it matters, and read the console. Screenshots are in `web/screenshots/feature/`.
- The scripts are in `~/Code/scratch/shotmatch-agents/feature-work/`:
  - per area: `simple.mjs`, `studio-camera.mjs`, `studio-objects.mjs`, `studio-time.mjs`, `studio-panels.mjs`, `studio-more.mjs`
  - the anywhere and placement checks: `anywhere*.mjs`, `approx.mjs`, `aim.mjs`, `placeshoot.mjs`, `studio-place.mjs`
  - `web/scripts/feature-smoke.mjs` re-runs the core paths.
- AI calls were kept to one or two per path. No texts or calls went to real numbers; email invites went to example.com. All 27 scratch shoots were deleted at the end.
- Most runs used software GL. Headless Chrome on linuxbox's integrated GPU lost its WebGL context under load; the app now keeps Simple usable when that happens (re-tested).

## Not testable here

These need hardware, accounts or spending the test must not use. Each was checked up to the request where that was possible.

- Enter VR: the button only shows when the browser reports `immersive-vr`; headless Chrome does not, so it never appears.
- Walk on a phone: Gyro, the look pad and the joystick need a touch device with motion sensors.
- Scout compass and arrow: the test phone had GPS (a fixed position) but no compass, and the page said so plainly ("No compass on this device. Head SW (228°)").
- Speak replies (Magpie): would play audio on every reply; not switched on.
- Voice call (ElevenLabs over Photon): not started, per the brief. The call path stops at Photon's number.
- Photon sending to real numbers: not done, per the brief. Invites went to test@example.com and showed the honest "won't let ShotMatch message ... first" note.

## Suspicions from reading the code, not seen failing

From the control inventory (a static read of web/src). None of these showed up as a wrong result in the runs above, so they are not in the failure list.

- `NewShootWatcher` (`Studio.tsx:1250`) opens the newest shoot with a matching spot id and keeps no baseline, so a person who already had a shoot at that exact place could land in the old one.
- The Aspect buttons offer 4:3, 4:5, 3:2 and 16:9, but the default can be 1:1 or 65:24, which leaves no button pressed.
- Walk's "Stand here as Cam A" is hard-coded; a renamed shot camera keeps the old label.
- `Drop.tsx`'s window paste handler also fires while the link box has focus; pasting an image there starts a shoot.
- `Outliner.tsx` defines `Row` and `Group` inside render, so rows remount on every change; keyboard focus on a row can be lost.
- The shared `overlays` column in `shot_settings` is never written; guides are per person.

## Re-running

- Core paths: `cd web && node scripts/feature-smoke.mjs` (defaults to https://app.tesseraphoto.com) (add `--render` for one AI render, `--keep` to keep the shoot). It makes its own shoot from the example photo, prints PASS or FAIL per path, and deletes the shoot through the Share sheet. Software GL is the default; `GL=gpu` uses the integrated GPU.
- Everything: the per-area scripts in `~/Code/scratch/shotmatch-agents/feature-work/` take a session label from `session.json`; `node report.mjs` rebuilds this file from their results.
